# 项目规划

本文档确立个人博客作品的技术底座、目录结构与开发顺序。开发顺序遵循一条原则：功能与流畅性优先，视觉打磨置于末位。

## 一、技术底座

### 选型结果

| 层次 | 选型 | 引入方式 |
| --- | --- | --- |
| 页面结构 | 语义化 HTML5，静态多页面 | 无 |
| 样式 | 原生 CSS，自建设计令牌与组件类 | 无 |
| 脚本 | 原生 JavaScript，classic script | 无 |
| 图标 | Lucide | SVG 内联，按需复制 |
| 代码高亮 | highlight.js 11.12.0 | 文章页按需加载，本地 vendor |
| 公式渲染 | KaTeX 0.19.0 | 文章页按需加载，本地 vendor |
| 星河背景 | CSS 渐变与关键帧动画 | 无 |
| 构建 | 无构建步骤 | 无 |

第三方库以本地文件形式放入 `assets/vendor/`，随站点一起分发，file:// 环境同样可用。加载时机由 `assets/scripts/reader.js` 判断：页面存在代码块或公式时才请求对应脚本，设备档位为 low 与 minimal 时跳过。渲染库不进入首屏请求队列。

### 采用依据

1. 流畅性。无框架运行时，首屏开销集中在 HTML 与 CSS。动画只使用 transform 与 opacity，交由合成层处理，重排与重绘的出现面降到最小。
2. 兼容性。classic script 与相对地址的组合，使页面在 file:// 与静态托管两种环境下都能运行。ES module 在 file:// 下受跨源策略限制，外部模块与本地区块数据读取都会失败，因此不作为加载方式。
3. 赛事契合。赛事点名 HTML、CSS、JavaScript 三项技术，原生实现与技术说明一一对应。
4. 环境契合。本机 Node 位于 Windows 侧，构建链调用成本偏高，无构建方案在开发与验证环节更轻便。

### 未采用项

| 方案 | 未采用原因 |
| --- | --- |
| Vue、React、Svelte | 博客交互密度低，运行时开销超过收益 |
| Element Plus、Ant Design、Bootstrap | 默认观感趋同，体积与创意评分不匹配 |
| Tailwind CSS | 要取得可接受的体积，必须引入构建步骤 |
| Astro | 构建产物使用绝对地址，file:// 打开时资源加载失败 |

### 能力分级与降级

页面按访问端的实际条件划分四档，由 `assets/scripts/capability.js` 在首屏同步判定，结果写入 `data-cap`，供样式与脚本共同读取，并暴露为 `window.Capability`。

判定输入包含三组信号：User-Agent 中的功能机与老式移动浏览器特征、硬件与网络线索（逻辑核数、设备内存、省流模式、2G 级连接），以及运行时 API 的可用性（自定义属性、`matchMedia`、`requestAnimationFrame`、`IntersectionObserver`、`backdrop-filter`）。

| 档位 | 判定条件 | 允许项 |
| --- | --- | --- |
| high | 逻辑核数 8 以上且内存 4 GB 以上 | 全部动效与增强 |
| medium | 未命中其他条件的现代设备 | 动效、模糊、按需脚本 |
| low | 受限 UA、双核以内、内存 1 GB 以内、省流模式或 2G 级连接 | 静态内容与基础表现 |
| minimal | 功能机 UA，或缺少自定义属性等基础 API | 静态内容 |

high 与 medium 之外，`data-motion="reduced"` 生效，动画与过渡关闭，平滑滚动同步关闭。minimal 档位额外挂载 `assets/styles/lite.css`，该样式表不使用自定义属性、弹性布局与网格，保证功能机上仍能正确排版。

脚本侧通过 `Capability.allow(name)` 查询单项能力，通过 `Capability.load(name, src)` 决定是否注入高开销脚本。未获允许时返回 `false`，资源不会进入请求队列。

## 三、开发阶段

### 阶段一 技术底座

确定选型、目录结构与脚手架，建立开发与验证方式。产出为本文档与可运行的页面骨架。

验收标准：以 file:// 与静态托管两种方式打开首页，样式、脚本与主题切换均正常。

### 阶段二 内容与栏目结构

确定导航栏目、页面清单与内容组织方式。文章内容以静态 HTML 编写，不使用运行时解析，避免首屏出现内容闪现。

验收标准：页面清单与栏目关系完整，每页的内容职责清晰。

### 阶段三 页面与导航骨架

搭建各页面的语义化结构，完成响应式布局与导航，处理共享头部与底部的重复片段。

验收标准：375、768、1440 三种宽度下无横向滚动；键盘可以完成全部导航。

### 阶段四 内容模块与交互

实现文章列表与详情、作品陈列、个人介绍等模块，补充滚动出现动画与导航高亮。

验收标准：各页面内容完整、链接互通，滚动过程无掉帧。

### 阶段五 性能、兼容性与无障碍

在目标浏览器中逐项验证，核对首屏体积与渲染指标，检查焦点样式、ARIA 属性与颜色对比度。

验收标准：预算表内各项达标，Lighthouse 无障碍评分不低于 90。

### 阶段六 视觉打磨

调整设计令牌的配色、字体与间距节奏，补充星河主题的纹理与装饰元素。本阶段处于末位，前序阶段未完成时不进入。

记录项：

1. 取消站内链接的已访问变色。当前 `a:visited` 会把点击过的站内链接转为 `--color-link-visited`；站名 `.brand` 也会一并变色，原因是 `a:visited` 的优先级高于 `.brand`，`color: inherit` 被覆盖。

2. 待入场内容在整页截图中的可见性。`data-reveal` 元素依赖 IntersectionObserver 判定入场，不滚动页面的整页截图不会触发观察器，视口之外的内容维持隐藏状态。真实浏览过程不受影响，打印路径已由 `@media print` 兜住。

验收标准：整站观感统一，各断点下无破版。

### 阶段七 打包与交付

核对资源体积，按赛事要求命名压缩包，撰写包含设计理念与技术实现的设计说明。

验收标准：解压后双击 index.html 即可完整浏览。

## 四、性能与兼容性预算

| 维度 | 目标 |
| --- | --- |
| 首屏关键资源（HTML 与 CSS） | 未压缩 120 KB 以内 |
| 页面自带脚本 | 未压缩 40 KB 以内，capability、main、reader 三者合计约 18 KB |
| 按需第三方库 | 仅在文章页命中内容时加载，highlight.js 约 129 KB，KaTeX 约 273 KB 加字体 296 KB |
| 单页 DOM 节点 | 1500 以内 |
| 累计布局偏移 | 接近于零，媒体元素标注宽高 |
| 目标浏览器 | Chrome 与 Edge 105 以上、Firefox 110 以上、Safari 15.4 以上 |
| 响应式断点 | 375、768、1024、1440 |
| 动画属性 | 仅 transform 与 opacity |

## 五、验证方式

1. 静态托管。在项目根目录启动静态服务器，浏览器访问本地端口。
2. 本地文件。以 file:// 打开 index.html，核对样式、脚本与主题切换。
3. 浏览器矩阵。在 Chrome、Edge、Firefox 中抽查布局与交互。
4. 无脚本核对。关闭 JavaScript 后确认正文可读、导航可用。
5. 无障碍核对。Lighthouse 检查与键盘操作复核。
6. 宽度实测。以无头 Chrome 在目标宽度下逐页读取 `documentElement.scrollWidth` 与 `clientWidth`，两者之差不为零即判定横向溢出，同时统计越界元素与可见的可聚焦元素顺序。

阶段三的实测结果为：五个页面在 360、753、1425 三种视口下溢出量均为 0；导航在 768 以下折叠为按钮、以上展开为横向列表；明暗两套主题下图标显示状态正确；可聚焦元素顺序为跳转链接、站点名、导航项、主题按钮、导航按钮、内容链接。

窄宽度测量需要绕开一处环境限制：Windows 下无头 Chrome 的窗口存在最小宽度，`--window-size=375` 实际得到约 489 像素的视口。精确的窄宽度改用同源内嵌框架承载目标页面，在框架上设定宽度后再读取内部文档的滚动宽度。

阶段五的核对结果：五个页面的 Lighthouse 无障碍评分均为 100，无失败审计项。剥离页面自带脚本后，正文仍然可读，导航常驻显示，主题切换与导航折叠两个按钮隐藏，待入场元素保持可见，横向溢出为 0。首屏资源方面，首页为 29.6 KB，文章列表、作品、关于三页在 26.4 至 27.9 KB 之间，文章详情页为 47.9 KB；按需第三方库在页面命中代码块与公式时另外计入。

无脚本核对的做法是复制站点并剥离页面自带脚本，再用探针读取计算样式。无头 Chrome 的 `--blink-settings=scriptEnabled=false` 会令截图静默失败，`--disable-javascript` 在当前版本下不生效，因此改用剥离脚本的副本。

多引擎渲染抽查结果：Firefox 下布局、公式、代码高亮、目录、代码块工具条与折叠均正常，差异集中在整页截图，见阶段六记录项 2。Edge 与 Chrome 同属 Chromium 引擎，当前环境下 Edge 无头模式无法顺利生成截图，未单独实测。
