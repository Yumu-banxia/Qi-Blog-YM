按访问端能力分级，把高开销表现留给用得上的人

2026-10-12兼容性

  • 兼容性
  • 渐进增强
  • 降级策略

同一份页面要在两台差异极大的设备上都可读，一台是星号键还在用的功能机，一台是当下的桌面浏览器。做法是在首屏同步判断一次访问端的条件，把结果写入根元素的 data-cap，之后样式与脚本都读这一处标记。

三处判定信号

第一处是 User-Agent。功能机与老式移动浏览器的特征片段归为一组，命中即判为最低档；现代内核但硬件受限的机型归为另一组，命中即判为受限档。

第二处是硬件与网络线索：逻辑核数、设备内存、省流模式，以及连接类型处于 2G 级的情形。

第三处是运行时接口的可用性：CSS.supports('--probe: 0')、matchMedia、requestAnimationFrame、IntersectionObserver、backdrop-filter，以及画布上下文能否取得。基础接口缺失时，脚本与样式的增强部分都无法成立。

四档与允许项

判定条件与各档允许的表现项
档位 判定条件 允许项
high 逻辑核数 8 以上，内存 4 GB 以上，且未偏好减少动态效果 全部动效与增强
medium 未命中其他条件的现代设备 动效、模糊、按需脚本
low 受限 UA、双核以内、内存 1 GB 以内、省流模式或 2G 级连接 静态内容与基础表现
minimal 功能机 UA，或缺少自定义属性等基础接口 静态内容

样式与脚本如何读取

样式直接按属性选择器分支处理。受限档位下页头的模糊背景被关掉，最低档位下导航改为常驻排列，两个按钮隐藏，动画与过渡整体停用。

脚本通过 Capability.allow(name) 查询单项能力，通过 Capability.load(name, src) 决定是否注入高开销脚本。未获允许时返回 false，资源不进入请求队列，这一点比加载之后再判断更省。

var tier = 'medium';
var reason = 'baseline';
var limited = (cores > 0 && cores <= 2) || (memory > 0 && memory <= 1);

if (legacyUA || !env.customProperties || !env.matchMedia || !env.animationFrame) {
  tier = 'minimal';
  reason = legacyUA ? 'legacy-ua' : 'limited-runtime';
} else if (CONSTRAINED_PATTERN.test(ua) || limited || saveData || slowNetwork) {
  tier = 'low';
  reason = (saveData || slowNetwork) ? 'network' : 'hardware';
} else if (cores >= 8 && memory >= 4 && !prefersReducedMotion) {
  tier = 'high';
  reason = 'ample';
}

var features = {
  effects: tier === 'high' || tier === 'medium',
  motion: (tier === 'high' || tier === 'medium') && !prefersReducedMotion,
  blur: env.blur && (tier === 'high' || tier === 'medium'),
  optionalScripts: tier === 'high' || tier === 'medium'
};

root.setAttribute('data-cap', tier);
root.setAttribute('data-cap-reason', reason);

最低档位换一套样式

仅有静态内容还不够。缺少自定义属性与弹性布局支持时，主样式表本身就无法正确排版，因此最低档位会追加一份兜底样式表。这份样式不使用自定义属性、弹性布局、网格与逻辑属性，正文以 16 像素、1.6 行高呈现，导航回到行内排列。

根元素上的 data-cap-reason 保留了判定来源，便于在真机上核对是哪一组信号触发了降级。

小结

分级的意义在于把表现层的开销与访问端的实际条件对齐。判断只做一次，写在根元素上，样式与脚本共用；判断结果与来源都留在文档里，便于复核。
