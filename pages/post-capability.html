老设备也要能读：按访问端条件分级

2026-10-12兼容性

  • 兼容性
  • 渐进增强
  • 降级策略

手边有一台 Nokia 2700c，试着打开这个站。结果比预想差：布局散掉，正文挤成一团。那次之后，站点加了一套按访问端条件分支的机制。

首屏判断一次

判断放在 <head> 里同步执行的一小段脚本中，结果写到根元素的 data-cap 上，样式和后续脚本都读这一个属性，不再各自判断。依据来自三处。

先是 User-Agent。功能机与老式移动浏览器（MIDP、Symbian、Opera Mini、Trident 这些片段）命中就判最低档；现代内核但硬件受限的机型（老 Android、UC、MIUI 之类）归为受限档。

再看硬件与网络：逻辑核数、设备内存、省流模式，以及连接是不是 2G 级。

最后一处是运行时接口是否可用：CSS.supports('--probe: 0')、matchMedia、requestAnimationFrame、IntersectionObserver、backdrop-filter，还有画布上下文。其中任一项缺失，脚本与样式的增强部分都无从成立。

四档与各自能用的东西

判定条件与各档允许的表现项
档位 判定条件 允许项
high 逻辑核数 8 以上，内存 4 GB 以上，且未偏好减少动态效果 全部动效与增强
medium 未命中其他条件的现代设备 动效、模糊、按需脚本
low 受限 UA、双核以内、内存 1 GB 以内、省流模式或 2G 级连接 静态内容与基础表现
minimal 功能机 UA，或缺少自定义属性等基础接口 静态内容

样式与脚本怎么读这个结果

样式按属性选择器分支。受限档位关掉页头模糊；最低档位把导航改回常驻排列，隐藏搜索与主题按钮，动画和过渡整个停掉。

脚本用 Capability.allow(name) 与 Capability.load(name, src)。未获权限时 load 返回 false，请求不会发出，比先下载再判断更省。

var tier = 'medium';
var reason = 'baseline';
var limited = (cores > 0 && cores <= 2) || (memory > 0 && memory <= 1);

if (legacyUA || !env.customProperties || !env.matchMedia || !env.animationFrame) {
  tier = 'minimal';
  reason = legacyUA ? 'legacy-ua' : 'limited-runtime';
} else if (CONSTRAINED_PATTERN.test(ua) || limited || saveData || slowNetwork) {
  tier = 'low';
  reason = (saveData || slowNetwork) ? 'network' : 'hardware';
} else if (cores >= 8 && memory >= 4 && !prefersReducedMotion) {
  tier = 'high';
  reason = 'ample';
}

var features = {
  effects: tier === 'high' || tier === 'medium',
  motion: (tier === 'high' || tier === 'medium') && !prefersReducedMotion,
  blur: env.blur && (tier === 'high' || tier === 'medium'),
  optionalScripts: tier === 'high' || tier === 'medium'
};

root.setAttribute('data-cap', tier);
root.setAttribute('data-cap-reason', reason);

最低档位换一份样式表

仅有静态内容还不够。缺少自定义属性与弹性布局支持的浏览器，连主样式表都排不对，所以最低档位会追加一份兜底表：不用自定义属性，不用 flex 与 grid，正文 16 像素、行高 1.6，导航回到行内排列。

根元素上的 data-cap-reason 记着是哪组信号触发的降级（legacy-ua、network、hardware），在真机上排查时很省事。

没解决的部分

内存与核数的阈值是估出来的，只在几台常见设备上核对过，没有做大规模验证；功能机实测也只有那一台。要做扎实，需要收集一批旧机型逐台验证，这一步尚未进行。
