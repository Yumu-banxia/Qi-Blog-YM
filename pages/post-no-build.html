本地双击与静态托管：无构建方案的取舍

2026-10-11技术选型

  • 技术选型
  • 性能预算
  • 静态站点

作品以压缩包提交，评审端可能从解压目录双击打开 index.html，发布端则采用静态托管。项目因此将 file:// 与静态托管同时列为支持环境，并选择无构建的文件结构。

本地文件与静态托管

最初的实现使用 ES module。通过 file:// 打开页面时，外部模块被浏览器按跨源请求处理，脚本无法执行；以 fetch 读取本地数据文件也会被拦截。改用 classic script、资源引用统一写作相对地址之后，页面在本地与静态托管两种环境下行为一致。

静态站点生成器的产物通常假定站点位于域名根目录，样式与脚本使用 /assets/... 形式的根相对地址。压缩包解压后的目录层级由评审环境决定，这类地址在本地无法解析。交付形式与构建产物之间因此产生冲突，多数生成器失去适用性。

<link rel="stylesheet" href="../assets/styles/tokens.css?v=8">
<link rel="stylesheet" href="../assets/styles/base.css?v=8">
<script src="../assets/scripts/capability.js?v=8"></script>
<script src="../assets/scripts/main.js?v=8" defer></script>

首屏体积预算

项目设定两项上限：HTML 与样式表合计不超过 120 KB，页面自带脚本不超过 40 KB，均按未压缩体积计算；KB 按 1024 字节换算。2026-10-17 的本地统计中，首页 HTML、样式表与页面脚本合计 80.8 KB，gzip 后 22.1 KB；文章列表 52.6 KB，关于 51.7 KB，归档 55.7 KB，作品 58.8 KB；文章详情页 80.4 KB 至 82.6 KB，gzip 后 22.4 KB 至 23.0 KB，差异主要来自正文。

每页共同加载的 capability.js 与 main.js 合计约 15.3 KB。首页额外加载星图脚本，文章页额外加载阅读脚本；搜索脚本与索引在打开搜索面板后才请求。highlight.js 与 KaTeX 仅在页面存在代码块或公式时进入加载队列。

多页结构的维护成本

页头与页脚在每份文档中各存一份，导航改动需要同步八个文件。新增「归档」栏目时，批量替换由脚本完成，带 aria-current 的当前页仍需单独处理。页面数量继续增加会使手工维护的负担超过收益，项目因此约定：文件超过八个之后改用一次性生成脚本，脚本只在开发阶段运行，交付物仍为静态文件。

组件库与 CSS 框架

构建步骤会影响组件库的引入方式。组件库通常借助打包工具的 tree shaking 按需引入；无构建条件下需要加载完整样式，再覆盖默认规则。当前三份样式表分别 gzip 后合计约 10.6 KB，覆盖现有页面的界面需求；引入通用组件库仍需按其变量体系重写样式，因此未纳入方案。

原子化 CSS 框架依赖构建期扫描与生成，运行时方案需要额外脚本解析类名，与首屏预算冲突。

无构建方案的维护边界

无构建流程不会自动执行类型检查、测试或第三方依赖更新；项目通过独立 Node 脚本核对内容、浏览器行为与无障碍状态。vendor 目录中的库文件以及样式和脚本版本仍需手动维护，页面增加后，重复维护页头与页脚的成本也会提高。
